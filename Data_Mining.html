Unit I – Introduction and Data Preprocessing

1.1 Fundamentals of Data Mining

Data mining means digging out useful, hidden and previously unknown patterns from very large collections of data. The name comes from gold mining: you move a mountain of soil (raw data) to find a few nuggets of gold (knowledge). It is also known as KDD – Knowledge Discovery from Data, although strictly, data mining is the central step of the larger KDD process.

Why do we need it? Today banks, shops, hospitals, mobile networks and websites record billions of facts every day. We are "data rich but information poor". A human cannot read ten million bills to understand what customers like, but an algorithm can. Data mining turns this stored data into decisions: which customers may leave, which transactions may be fraud, which products should be placed together.

Steps of the KDD process

  1. Data cleaning – remove noise and fix inconsistent data.
  2. Data integration – combine data coming from several sources.
  3. Data selection – retrieve only the data relevant to the analysis task.
  4. Data transformation – convert data into forms suitable for mining, e.g. by summarising or normalising.
  5. Data mining – apply intelligent methods to extract patterns.
  6. Pattern evaluation – identify the truly interesting patterns using measures like support and confidence.
  7. Knowledge presentation – show the result with charts, tables and reports.

Architecture

A typical system has data sources (databases, warehouse, web), a database or warehouse server, a knowledge base (concept hierarchies, user beliefs), the mining engine, a pattern evaluation module and a user interface. The kinds of data that can be mined include relational databases, data warehouses, transactional data, spatial, time-series, text, multimedia, data streams and the World Wide Web.

1.2 Data Mining Functionalities

Functionalities specify the kinds of patterns a mining task can discover. They fall into two groups: descriptive tasks describe the general properties of the existing data, while predictive tasks use the existing data to make predictions about future or unknown values.

  • Concept/class description – summarises a group of data. Characterization gives a short summary of the target class (for example, the common features of customers who spend more than ₹50,000 a year). Discrimination compares the target class with other classes (high spenders versus low spenders).
  • Association analysis – finds items that occur together. Example rule: buys(bread) ⇒ buys(butter) [support = 5%, confidence = 70%]. Support says how often the items appear together; confidence says how often butter is bought when bread is bought. Market-basket analysis is the classic use.
  • Classification – builds a model (decision tree, neural network, Bayesian classifier) from training data whose class labels are known, and uses it to label new data, such as "loan applicant is safe or risky".
  • Prediction – estimates a missing or future numeric value, such as next month's sales, normally by regression.
  • Clustering – groups objects into clusters when class labels are unknown. The principle is to maximise similarity inside a cluster and minimise similarity between clusters.
  • Outlier analysis – detects objects that do not follow the general pattern. One person's noise is another's signal; for instance, an unusual card purchase may indicate fraud.
  • Evolution analysis – studies how data changes over time, including trends, periodicity and similarity search in time-series data, such as share prices.
Remember: Classification is supervised (labels known). Clustering is unsupervised (labels unknown). Not every discovered pattern is useful; a pattern is "interesting" if it is easy to understand, valid on new data, potentially useful and novel.

1.3 Classification of Data Mining Systems

Data mining is an interdisciplinary field that borrows from database systems, statistics, machine learning, pattern recognition, visualisation, information retrieval and high-performance computing. Because so many kinds of systems exist, it helps to classify them. This helps users choose the right software for their need, and helps researchers see gaps in the field.

  • By the kind of database mined – a system can be called relational, transactional, object-relational, spatial, time-series, text, multimedia, heterogeneous, legacy or Web mining system, depending on the data model or data type it handles. A system that mines relational data is a relational miner; one that mines spatial data is a spatial miner.
  • By the kind of knowledge mined – based on functionality: characterization, discrimination, association, classification, clustering, outlier analysis, evolution analysis. A comprehensive system provides many functions together. Systems may also mine knowledge at one level or at multiple levels of abstraction, and may mine regularities (common patterns) or irregularities (exceptions).
  • By the kind of techniques utilised – by the degree of user interaction (autonomous, interactive exploratory, query-driven) and by the data analysis method (database-oriented, data-warehouse/OLAP-oriented, machine learning, statistics, visualisation, pattern recognition, neural networks).
  • By the applications adapted – systems built for finance, telecommunications, retail, biology, DNA analysis, the stock market, intrusion detection and so on. Generic tools may not fit these tasks, so application-specific methods are used.

An ideal data mining system should integrate smoothly with a database or warehouse system. Coupling schemes are: no coupling, loose coupling, semi-tight coupling and tight coupling. Tight coupling is best because mining becomes a part of the DB system, giving fast and scalable processing.

1.4 Major Issues in Data Mining

Data mining is powerful but faces challenges, grouped into five categories.

Mining methodology issues

Different users want different knowledge, so a system must mine different kinds of knowledge from the same data. It must allow mining at multiple levels of abstraction (drill-down and roll-up). It must handle noisy and incomplete data, because real data has errors and gaps. It must judge pattern interestingness, since a mining run can produce thousands of patterns and most are useless. It should use background knowledge such as concept hierarchies to guide the search.

User interaction issues

Mining should be interactive: the user should be able to refine the query, focus on part of the data and change the level. A data mining query language (like SQL for databases) is needed so that tasks can be specified easily. The results should be shown in high-level, understandable forms: graphs, rules, tables, visualisations.

Performance issues

Algorithms must be efficient and scalable for data of gigabytes or terabytes; running time must be predictable and acceptable. Because databases are large and distributed, parallel, distributed and incremental algorithms are required. Incremental methods update patterns when new data arrives without starting again.

Diversity of data types

Systems must handle relational and complex data (multimedia, text, spatial, time-series), and mine from heterogeneous databases and global information systems such as the Web, where formats and meanings differ.

Social issues

Mining may threaten privacy by profiling individuals, raise security concerns and lead to misuse of discovered knowledge. Protecting data (anonymisation, privacy-preserving mining) is an important challenge.

1.5 Data Preprocessing: Why Is It Needed?

Raw data collected in real life is almost never ready for mining. It is usually dirty in three ways:

  • Incomplete – some attribute values are missing, or only summary data is available. A customer's income may be left blank in a form, or the machine may have stopped recording.
  • Noisy – the data contains errors or outliers, such as age = −10 or salary = 10,000,000 because of typing mistakes or faulty sensors.
  • Inconsistent – the same thing is stored in different ways: rating "1, 2, 3" in one table and "A, B, C" in another; or the same customer appears with two spellings.

The reasons are many: faulty instruments, human or computer error during entry, transmission errors, different data sources with different conventions, and duplicate records. If we mine such data, the discovered patterns will also be poor: garbage in, garbage out. Quality decisions need quality data.

Data quality is measured by accuracy, completeness, consistency, timeliness, believability and interpretability. Preprocessing improves these and makes mining faster, more accurate and easier. Major preprocessing tasks are data cleaning, data integration, data transformation, data reduction and data discretization. These tasks are not strictly separate; for example, removing redundant attributes is both integration and reduction. In practice preprocessing often takes more than half of the total effort in a data mining project, which shows how important it is.

1.6 Data Cleaning

Data cleaning (data cleansing) fills in missing values, smooths noisy data, identifies or removes outliers and resolves inconsistencies. Users will not trust results from a system that works on dirty data.

Handling missing values

  1. Ignore the tuple – easy but wasteful, especially when many values are missing.
  2. Fill in manually – accurate but too slow for large data.
  3. Use a global constant such as "Unknown" – simple, but the miner may treat "Unknown" as an interesting value.
  4. Use the attribute mean or median – the median is better for skewed data.
  5. Use the class-wise mean – the mean of tuples belonging to the same class.
  6. Use the most probable value – predicted with regression, a decision tree or Bayesian inference. It is the most popular and accurate method.

Handling noisy data

Binning sorts the data and distributes it into equal-size bins; values are smoothed using their neighbours. Example: sorted prices 4, 8, 15, 21, 21, 24, 25, 28, 34 in three bins: (4, 8, 15), (21, 21, 24), (25, 28, 34). Smoothing by bin means gives (9, 9, 9), (22, 22, 22), (29, 29, 29). Smoothing by bin boundaries replaces each value by the nearest boundary: (4, 4, 15), (21, 21, 24), (25, 25, 34).

Regression fits the data to a function (linear or multiple) and replaces noisy values by the fitted ones. Clustering groups similar values; values falling outside all clusters are outliers.

Data cleaning as a process

Discrepancy detection uses metadata (domain, range, dependencies), rules (unique, consecutive, null rules) and commercial tools (data scrubbing, data auditing). Data migration tools and ETL tools then transform the data. The two steps are repeated in an iterative, interactive way.

1.7 Data Integration and Transformation

Data integration

Data integration merges data from multiple sources (databases, data cubes, flat files) into a single coherent store such as a data warehouse. Issues to handle:

  • Schema integration and entity identification – matching equal entities with different names, e.g. cust_id in one database and customer_number in another. Metadata helps to avoid errors.
  • Redundancy – an attribute is redundant if it can be derived from others (annual revenue from monthly revenue). Redundancy is found by correlation analysis. For numeric data the correlation coefficient is r = Σ(a−Ā)(b−B̄) / (n·σA·σB): r > 0 means positive correlation, r = 0 independent, r < 0 negative. For nominal data the χ² test is used. Duplicate tuples should also be detected.
  • Detection and resolution of data value conflicts – the same real-world value may differ between sources because of units (metric vs British), scale or encoding.

Data transformation

Transformation changes the data into forms suitable for mining:

  • Smoothing – removes noise (binning, regression, clustering).
  • Aggregation – summary operations, such as daily sales into monthly sales; used to build data cubes.
  • Generalization – low-level data replaced by higher-level concepts through hierarchies (street → city → country).
  • Normalization – scales values into a small range such as 0.0–1.0 so that large-valued attributes do not dominate distance calculations.
  • Attribute (feature) construction – new attributes built from existing ones, such as area = height × width.

1.8 Normalization Methods (part of Transformation)

Normalization is especially important for distance-based methods such as clustering, nearest-neighbour classification and neural networks. Suppose income is in thousands (12,000–98,000) and age is in tens (20–70); without normalization, income would swamp age.

  • Min-max normalization performs a linear change of the original data: v' = ((v − min) / (max − min)) × (new_max − new_min) + new_min. Example: income range 12,000–98,000 mapped to [0, 1]; for v = 73,600: (73,600 − 12,000)/(98,000 − 12,000) = 0.716. It preserves the relations among the original values but fails if a new input falls outside the original range.
  • Z-score normalization (zero-mean) uses the mean and standard deviation: v' = (v − mean) / σ. Example: mean = 54,000, σ = 16,000; v = 73,600 gives (73,600 − 54,000)/16,000 = 1.225. Useful when min and max are unknown or outliers dominate. A variation uses the mean absolute deviation instead of σ, which is more robust to outliers.
  • Normalization by decimal scaling moves the decimal point: v' = v / 10j, where j is the smallest integer such that max(|v'|) < 1. If values range from −986 to 917, j = 3, so −986 becomes −0.986 and 917 becomes 0.917.

Note that normalization changes the original data, so the parameters (min, max, mean, σ) should be saved to apply the same transformation to future data.

1.9 Data Reduction

A data warehouse may hold terabytes of data, and running complex mining on it may take very long. Data reduction obtains a reduced representation that is much smaller in volume but produces almost the same analytical results.

  1. Data cube aggregation – aggregation is applied to build cubes. The cube at the lowest level is the base cuboid; higher cuboids give summarised data. Queries are answered using the smallest relevant cuboid, e.g. yearly sales instead of per-transaction sales.
  2. Attribute subset selection – removes irrelevant or redundant attributes (such as phone number when predicting music taste). Heuristic methods: stepwise forward selection (start empty, add the best attribute), stepwise backward elimination (start with all, remove the worst), a combination of both, and decision tree induction (attributes not in the tree are dropped).
  3. Dimensionality reduction – encoding mechanisms reduce size. Discrete Wavelet Transform (DWT) keeps only strongest wavelet coefficients, giving lossy compression. Principal Component Analysis (PCA) finds k orthogonal vectors (principal components) that best represent the data, projecting n-dimensional data into k ≤ n dimensions.
  4. Numerosity reduction – replaces data with smaller forms. Parametric: regression and log-linear models store only parameters. Non-parametric: histograms (equal-width or equal-frequency buckets), clustering (store cluster centre and size), and sampling – SRSWOR (without replacement), SRSWR (with replacement), cluster sample and stratified sample.
  5. Data compression – lossless (original fully reconstructed, as in string compression) or lossy (only approximate reconstruction, as in image and audio compression).

1.10 Discretization and Concept Hierarchy Generation

Discretization reduces the number of values of a continuous attribute by dividing its range into intervals, and replaces actual values by interval labels. For example, age can become 0–18, 19–40, 41–65 and 66+. This makes data smaller, simpler and suitable for algorithms (like decision trees and association rules) that work on categorical data. It can be supervised (uses class information) or unsupervised, and top-down (splitting) or bottom-up (merging).

A concept hierarchy replaces low-level values with higher-level concepts: age 25 → young adult → adult → person. It allows mining at multiple levels of abstraction.

For numeric data

  • Binning – equal-width or equal-frequency bins, applied recursively; unsupervised.
  • Histogram analysis – partitions values into buckets, repeated until a stopping condition.
  • Cluster analysis – clusters become the intervals, and sub-clusters form lower levels.
  • Entropy-based discretization – supervised; picks the split point giving minimum entropy (maximum information gain) and recursively splits until a stop condition.
  • Interval merging by χ² analysis (ChiMerge) – starts with each value as an interval and merges adjacent intervals with similar class distribution.
  • Segmentation by natural partitioning (3-4-5 rule) – divides a range into 3, 4 or 5 equal intervals according to the most significant digit: 3, 6, 7 or 9 distinct values → 3 intervals; 2, 4 or 8 → 4 intervals; 5 or 10 → 5 intervals.

For categorical data

  • Explicit ordering by the user, e.g. street < city < state < country.
  • Specifying a group of attributes explicitly, with the system sorting them.
  • Specifying only a partial set of attributes.
  • Automatic generation by counting distinct values: the attribute with the most distinct values is placed at the lowest level (street has more values than country). Exceptions such as weekday are corrected by the user.

Unit II – Data Warehouse and OLAP Technology for Data Mining

2.1 Data Warehouse: Meaning and Features

A data warehouse is a large, central repository of information collected from many different sources (sales system, HR system, web logs) and stored under one unified schema. It is built to support management decisions, not day-to-day transactions. In the words of W. H. Inmon, it is a subject-oriented, integrated, time-variant and non-volatile collection of data that supports management's decision-making process.

  • Subject-oriented – organised around major subjects such as customer, supplier, product and sales, rather than around operations such as billing or inventory update. It excludes data not useful for decisions.
  • Integrated – built by merging several databases, flat files and online records. Data cleaning and integration make naming, coding and units consistent (e.g. "M/F" and "Male/Female" become one format).
  • Time-variant – stores historical information (5–10 years). Every key structure contains a time element, so trends and changes can be studied.
  • Non-volatile – data is physically separate from the operational database. Updates, deletes and transaction processing do not happen in the warehouse; only initial loading and read access (periodic refresh) are needed.

Data warehousing is the process of constructing and using a warehouse: cleaning, integration, transformation, loading and periodic refresh. It differs from a traditional heterogeneous DB integration (query-driven approach, where a query is translated for each source) because it uses an update-driven approach: information is integrated in advance and stored, giving high performance for analysis.

Why keep a separate warehouse? (OLTP vs OLAP)

Operational systems (OLTP) are tuned for fast, small transactions. Warehouse queries (OLAP) are complex, scan huge data and need summarised, historical views. Running them on the operational database would slow down daily business and lock data.

2.2 Multidimensional Data Model: Data Cube

Warehouses and OLAP tools use a multidimensional model, where data is viewed as a data cube. A cube lets data be modelled and seen in many dimensions. It is defined by dimensions and facts.

  • Dimensions are the perspectives or entities with respect to which an organisation wants to keep records, e.g. time, item, branch, location. Each dimension has a dimension table (e.g. item(item_name, brand, type)).
  • Facts are numeric measures, e.g. dollars_sold, units_sold, budget. They are stored in a fact table, which contains the measures plus keys to each dimension table.

A 2-D view shows, for example, time × item for one location. Adding location gives a 3-D cube; adding supplier gives a 4-D cube, which is seen as a series of 3-D cubes. Every combination of dimensions forms a cuboid. The lowest-level cuboid holding all dimensions is the base cuboid; the highest-level one that summarises everything (a single value, e.g. total sales) is the apex cuboid. Together, the lattice of cuboids is the data cube. For n dimensions with no hierarchies there are 2n cuboids; if dimension i has Lᵢ levels, the total is Π(Lᵢ + 1).

Concept hierarchies

A concept hierarchy maps low-level concepts to higher-level ones. For location: street < city < province < country (total order); for time: day < {month, week} < quarter < year (partial order, since weeks do not fit exactly into months). Hierarchies make roll-up and drill-down possible.

Types of measures

  • Distributive – can be computed by partitioning the data, aggregating each part, then aggregating again: sum, count, min, max.
  • Algebraic – computed from a fixed number of distributive measures: average = sum/count, standard deviation.
  • Holistic – no fixed-size sub-result can describe it: median, mode, rank. These are hard to compute in cubes.

2.3 Schemas for Multidimensional Databases

A schema is the logical design of the warehouse, showing how fact and dimension tables are linked.

Star schema

The most common model. A large central fact table (no redundancy) is connected to a set of dimension tables, one per dimension, so the picture looks like a star. Each dimension table may contain redundancy since hierarchies are flattened in one table (e.g. the location table repeats country for every city). Advantage: simple, few joins, fast queries. Disadvantage: redundant data.

Snowflake schema

A variant where some dimension tables are normalised into additional tables, so the diagram looks like a snowflake. For example, item → supplier, and location → city. It saves storage and reduces redundancy, but needs more joins, which slows queries and makes browsing harder. Therefore it is less popular than the star schema.

Fact constellation (galaxy schema)

Sophisticated applications need multiple fact tables sharing dimension tables, like a collection of stars. Example: a Sales fact table and a Shipping fact table both using the time, item, location dimensions. Used for enterprise-wide warehouses.

Data warehouse vs data mart: Enterprise-wide design usually uses a fact constellation; a department-level data mart (a subset of the warehouse for one group, such as marketing) generally uses a star or snowflake schema.

2.4 OLAP Operations in the Multidimensional Model

OLAP (On-Line Analytical Processing) offers interactive operations on a cube so that the user can look at data from different angles and levels. The typical operations are:

  • Roll-up (drill-up) – aggregates data by climbing up a concept hierarchy (city → country) or by dimension reduction (removing a dimension). Result: less detail.
  • Drill-down – the reverse: goes from less detailed to more detailed data by moving down a hierarchy (quarter → month) or adding a dimension. Dimension values need to be available at the lower level.
  • Slice – selects a single value on one dimension, producing a sub-cube. Example: time = "Q1" gives a plane of item × location.
  • Dice – selects values on two or more dimensions, producing a smaller sub-cube: (location = Delhi or Patna) and (time = Q1 or Q2) and (item = phone or laptop).
  • Pivot (rotate) – rotates the axes of the view to give another presentation, e.g. swapping item and location axes in a 2-D table.
  • Other operations – drill-across (queries involving more than one fact table) and drill-through (go down to the back-end relational tables), top-N/bottom-N ranking, and statistical computations like moving average.

OLAP operations must give answers quickly, even for terabytes of data, which is why special storage and indexing techniques (Section 2.7) are used.

2.5 Data Warehouse Architecture

Steps in design and construction

First, choose the business process (e.g. orders, billing) and the grain (the atomic level of the fact table); then choose dimensions and measures. Design may be top-down (enterprise plan first), bottom-up (start with experimental data marts), or a combined approach. Software engineering models like waterfall and spiral can be applied.

Three-tier architecture

  1. Bottom tier – warehouse database server: almost always a relational DBMS. Data from operational databases and external sources is fed using back-end tools and utilities that perform extraction, cleaning, transformation (ETL), load and refresh. This tier also holds the metadata repository and a monitor/integrator.
  2. Middle tier – OLAP server: implemented as ROLAP, MOLAP or HOLAP; presents multidimensional views to the client.
  3. Top tier – front-end client layer: query and reporting tools, analysis tools, and data mining tools (trend analysis, prediction).

Warehouse models

  • Enterprise warehouse – collects information about all subjects across the entire organisation; needs extensive business modelling; size from GB to TB.
  • Data mart – a subset of corporate data for a specific group of users. Independent marts take data from operational systems directly; dependent marts take it from an enterprise warehouse.
  • Virtual warehouse – a set of views over operational databases. Easy to build, but needs excess capacity on operational servers.

2.6 Metadata Repository and OLAP Server Types

Metadata is "data about data". It defines warehouse objects and guides loading, access and administration. It includes:

  • A description of the warehouse structure: schema, views, dimensions, hierarchies, derived data definitions, data mart locations.
  • Operational metadata: data lineage (history of migrated data and transformations), currency of data (active, archived, purged), monitoring information (usage statistics, error reports, audit trails).
  • The algorithms used for summarisation and the mapping from the operational environment to the warehouse (source databases, extraction, cleaning rules).
  • Data related to system performance: indices, profiles, refresh rules; and business metadata: business terms, ownership, charging policies.

2.7 Data Warehouse Implementation

Warehouses must give very fast answers on huge volumes. Implementation therefore focuses on efficient cube computation, selection of what to precompute, indexing and query processing.

Efficient computation of data cubes

The compute cube operator (e.g. CUBE BY item, city, year) computes aggregates over all subsets of the dimensions, giving 2n group-bys. This can need huge storage, especially with hierarchies. Choices: full materialisation (precompute all cuboids – fast queries, much storage), no materialisation (compute on the fly – slow), or partial materialisation (select a suitable subset). Methods to compute: sort/hash sharing, multiway array aggregation (chunks the array and aggregates several cuboids at once), and BUC (bottom-up computation) which also supports iceberg cubes that keep only cells meeting a minimum threshold (e.g. count ≥ 100), pruning using the Apriori idea.

Selecting cuboids to materialise

A greedy algorithm picks cuboids that give the biggest benefit per unit of storage, considering query frequency and size. The shell fragments method precomputes small groups of dimensions for high-dimensional data.

Indexing OLAP data

  • Bitmap index – for each distinct value of an attribute, a bit vector marks the rows containing it. Joins and aggregations become fast bit operations (AND, OR). Best for low-cardinality attributes (gender, region).
  • Join index – precomputes the join between a dimension table and the fact table by storing, for each dimension value, the list of matching fact-table row IDs. Bitmapped join indices combine both ideas.

Efficient processing of OLAP queries

(1) Determine which operations are performed on the available cuboids (translate roll-up, drill-down, slice and dice into selections, projections, group-by). (2) Determine which materialised cuboids are relevant and pick the one with the lowest cost (smallest size), then use indices to speed access.

2.8 Further Development of Data Cube Technology

Basic cubes only report aggregated values. Newer techniques make cubes more intelligent and efficient for analysis.

Discovery-driven exploration of data cubes

In hypothesis-driven exploration the analyst must guess where interesting data hides and drill down by trial and error, which is tiring in large cubes. In discovery-driven exploration, precomputed measures indicate exceptions automatically: a cell value is an exception if it differs significantly from the value expected by a statistical model using the cell's position and its neighbours. Three measures guide the user, shown as visual cues (colour shades): SelfExp (surprise of the cell itself), InExp (surprise hidden beneath the cell, when drilling down) and PathExp (degree of surprise for each drill-down path). The analyst quickly sees where to explore.

Complex aggregation at multiple granularities: multifeature cubes

Traditional cubes compute simple aggregates. Multifeature cubes compute complex queries with several dependent aggregates at multiple granularities. Example: "For each item and region, find the maximum price in 2025, and the total sales among all tuples that have that maximum price." The second aggregate depends on the first. Such queries are expressed with extended SQL, using grouping variables, and computed efficiently using techniques similar to ordinary cube computation.

Other advances

  • Prediction cubes – integrate prediction models (like classifiers) with cubes to explore prediction accuracy at different levels.
  • Sampling cubes – use sampling for statistically reliable answers when only a sample of the data is available.
  • Ranking cubes – efficiently answer top-k queries.
  • Cube gradient analysis – find cells whose measure changes strongly compared to ancestors, siblings or descendants.

2.9 From Data Warehousing to Data Mining

Data warehouse usage

Warehouses are used in three stages: (1) information processing – querying, basic statistical analysis, reporting with tables, charts and graphs; (2) analytical processing – multidimensional analysis with OLAP operations such as slice, dice, drill-down and roll-up, on summarised and detailed historical data; (3) data mining – discovering hidden patterns and associations, building classification and prediction models, and presenting results with visual tools. Mining goes one step beyond OLAP: OLAP summarises and compares data, while mining finds new knowledge automatically.

From OLAP to OLAM

On-Line Analytical Mining (OLAM), also called OLAP mining, integrates OLAP with data mining so that mining is done in multidimensional databases, interactively and at various levels of abstraction. It is attractive for four reasons:

  • High quality of data in warehouses – data is already cleaned, integrated and consistent, so preprocessing cost is saved.
  • Available information-processing infrastructure – access methods, ODBC/OLE DB connections, OLAP tools and reporting are already built around warehouses.
  • OLAP-based exploratory data analysis – the user can slice, dice, drill and pivot to focus on interesting subsets before and during mining.
  • On-line selection of data mining functions – the user can switch between characterization, association, classification, prediction and clustering interactively, on any chosen portion of the cube.

OLAM architecture

An OLAM engine sits beside the OLAP engine; both work on the same multidimensional database (data cube) through an API, with a data warehouse underneath. The user interface (GUI API) sends tasks to the OLAM or OLAP engine, and the cube is built from the warehouse after cleaning and integration. Thus a user can run a mining function after OLAP operations in the same environment.

Unit III – Concept Description: Characterization and Comparison

3.1 Data Generalization and Summarization-Based Characterization

Concept description gives a short, understandable summary of a collection of data (a class). Characterization summarises the general features of the target class; comparison (discrimination) compares target and contrasting classes.

Attribute-Oriented Induction (AOI)

AOI generalises data by moving up concept hierarchies. Steps:

  1. Data focusing: collect task-relevant data using a query.
  2. Attribute removal: remove an attribute if it has many distinct values and no generalisation operator (e.g. name).
  3. Attribute generalization: if there is a hierarchy, replace values by higher-level concepts (city → country).
  4. Attribute generalization control: use a threshold (attribute threshold) to stop when the number of distinct values is small enough.
  5. Aggregation: merge identical tuples and accumulate count.

The result is a generalized relation, which can be shown as a crosstab, bar chart, pie chart, or as a characteristic rule such as: grad_student(x) ⇒ (birth_place = Canada ∧ GPA = excellent) [t-weight = 53%].

Efficient implementation: instead of doing AOI repeatedly, a cube-based approach pre-computes generalisations.

3.2 Analytical Characterization: Analysis of Attribute Relevance

Some attributes are not useful for characterising a class. Attribute relevance analysis removes irrelevant or weak attributes before generalisation.

  • Information gain / entropy: Info(D) = −Σ pᵢ log₂ pᵢ. The attribute with higher information gain is more relevant to the class.
  • Other measures: Gini index, uncertainty coefficient, correlation coefficient, χ².

Steps

  1. Data collection of target and contrasting classes.
  2. Preliminary relevance analysis using conservative AOI to reduce attributes.
  3. Relevance analysis: calculate information gain for each remaining attribute and rank them.
  4. Remove attributes below a relevance threshold.
  5. Generate the concept description with AOI on the remaining attributes.

3.3 Mining Class Comparisons: Discriminating Between Different Classes

Class comparison finds features that distinguish the target class from the contrasting class (e.g. graduate vs undergraduate students).

Steps

  1. Data collection: get target and contrasting class data (two tables).
  2. Dimension relevance analysis: keep only relevant dimensions.
  3. Synchronous generalization: generalise both classes to the same abstraction level.
  4. Presentation: as tables, graphs or discriminant rules, showing t-weight (how typical the tuple is within its class) and d-weight (how well it discriminates it from other classes).

t-weight = count(tuple in class) / count(all tuples in class) and d-weight = count(tuple in target class) / count(tuple in all classes). A high d-weight means the tuple strongly distinguishes the target class.

3.4 Mining Descriptive Statistical Measures in Large Databases

Measuring central tendency

  • Mean = Σx / n; weighted mean = Σwᵢxᵢ / Σwᵢ.
  • Median: middle value of the sorted data. For grouped data: L + ((n/2 − F)/f) × w.
  • Mode: most frequent value (unimodal, bimodal...). mean − mode ≈ 3 × (mean − median) for moderately skewed data.

Measuring dispersion (spread)

  • Range = max − min.
  • Quartiles: Q1 (25th percentile), Q2 (median), Q3 (75th percentile). IQR = Q3 − Q1.
  • Five-number summary: Min, Q1, Median, Q3, Max → drawn as a boxplot. Outliers are usually values beyond 1.5 × IQR above Q3 or below Q1.
  • Variance: σ² = Σ(x − mean)² / n; standard deviation σ = √variance. σ = 0 means all values are equal.

Graphic displays

Histogram, quantile plot, Q-Q plot (compare two distributions), scatter plot (see relationship between two attributes), and loess curve (smooth trend line).

Unit IV – Mining Association Rules in Large Databases

4.1 Association Rule Mining

Finds interesting relationships among items in a data set. Classic example is market-basket analysis: which products are bought together.

  • Itemset: a set of items. A k-itemset has k items.
  • Rule: A ⇒ B (if A then B).
  • Support = P(A ∪ B) = number of transactions with both A and B / total transactions.
  • Confidence = P(B | A) = support(A ∪ B) / support(A).
  • Strong rule: satisfies both minimum support and minimum confidence.
  • Frequent itemset: support ≥ minimum support.

Two steps: (1) find all frequent itemsets; (2) generate strong rules from them.

4.2 Mining Single-Dimensional Boolean Association Rules (Apriori)

"Single-dimensional" means only one predicate (e.g. buys). "Boolean" means items are present or absent.

Apriori property

All non-empty subsets of a frequent itemset must also be frequent. So if an itemset is infrequent, all its supersets are infrequent and can be pruned.

Apriori algorithm

  1. Scan DB, count each item → L1 (frequent 1-itemsets).
  2. Join step: join Lₖ₋₁ with itself to form candidates Cₖ.
  3. Prune step: remove any candidate that has an infrequent subset.
  4. Scan DB, count candidates, keep those ≥ min support → Lₖ.
  5. Repeat until no more frequent itemsets.
  6. For each frequent itemset l, for each non-empty subset s, output s ⇒ (l − s) if confidence ≥ min confidence.

Example: Transactions T1{A,B,C}, T2{A,B}, T3{A,C}, T4{B,C}; min support = 2. L1 = {A:3, B:3, C:3}. C2 = {AB:2, AC:2, BC:2}, all frequent. C3 = {ABC:1} → not frequent, stop. Rule A ⇒ B has confidence 2/3 = 66.7%.

Improving Apriori efficiency

  • Hash-based technique: hash buckets reduce candidate 2-itemsets.
  • Transaction reduction: drop transactions with no frequent k-itemsets.
  • Partitioning: split DB into parts; a global frequent itemset must be frequent in at least one partition (2 scans).
  • Sampling: mine a random sample with lower support.
  • Dynamic itemset counting: add new candidates while scanning.
  • FP-growth: builds a compact FP-tree and mines it by pattern growth, without candidate generation. Only 2 DB scans.

4.3 Mining Multilevel Association Rules

Items have concept hierarchies (food → bread → wheat bread). Strong rules at the low level are rare, so we mine at multiple levels.

  • Uniform minimum support: same threshold at all levels – simple, but may miss low-level rules or give too many high-level rules.
  • Reduced minimum support: lower threshold at lower levels (common approach).
  • Group-based support: special thresholds for important item groups.

Search strategies: level-by-level independent, level-cross filtering by single item, or by k-itemset. Redundant rules (a rule that can be derived from an ancestor rule) are removed.

4.4 Mining Multidimensional Association Rules from Relational Databases and Data Warehouses

Involves two or more predicates/dimensions, e.g. age(X, "20..29") ∧ occupation(X, "student") ⇒ buys(X, "laptop").

  • Inter-dimensional rules: no repeated predicates. Hybrid-dimensional: some predicates repeat (age ∧ buys ⇒ buys).
  • Attributes may be categorical or quantitative. Quantitative attributes are handled by:
    1. Static discretization using predefined hierarchies before mining.
    2. Dynamic discretization – quantitative association rules where ranges are formed during mining (e.g. ARCS clustering of rules).
    3. Distance-based – groups values by closeness.
  • A data cube can store counts and make mining quicker.

4.5 From Association Mining to Correlation Analysis

High support and confidence do not always mean a useful rule. Example: 60% of people buy a game, 75% buy a video, 40% buy both. Rule game ⇒ video has confidence 40/60 = 66%, which looks strong, but the video's base rate (75%) is higher, so buying a game actually reduces the chance of a video. So we need correlation measures.

  • Lift = P(A ∪ B) / (P(A) × P(B)).
    Lift > 1 → positive correlation; = 1 → independent; < 1 → negative correlation. (In the example: 0.40/(0.60×0.75) = 0.89 < 1.)
  • χ² (chi-square) test of independence.
  • Other measures: all_confidence, cosine measure.

Rules are therefore written as A ⇒ B [support, confidence, correlation].

4.6 Constraint-Based Association Mining

Instead of finding all rules, the user gives constraints so that only interesting rules are mined, faster.

Types of constraints

  • Knowledge-type: what to mine (association or correlation).
  • Data constraints: which data (e.g. sales in Bihar in 2025).
  • Dimension/level constraints: which dimensions, what concept levels.
  • Interestingness constraints: thresholds on support, confidence, lift.
  • Rule constraints: form of rules, e.g. metarules (templates like P1(X) ∧ P2(Y) ⇒ buys(X, ?)) or aggregate constraints (sum(price) < 100).

Property types

  • Anti-monotonic: if an itemset violates it, so do all its supersets → prune early (e.g. sum(price) ≤ 100 with non-negative prices).
  • Monotonic: if an itemset satisfies it, so do all its supersets (no need to re-check).
  • Succinct: satisfying sets can be generated directly.
  • Convertible: become anti-monotonic or monotonic when items are ordered suitably (e.g. avg()).

Unit V – Classification, Prediction and Cluster Analysis

5.1 Issues Regarding Classification and Prediction

Classification predicts categorical class labels (safe/risky). Prediction predicts continuous values (salary). Both are two-step processes: (1) learning/training step builds the model from training data with known labels (supervised learning); (2) classification step tests the model on test data, then uses it for new data.

Data preparation

  • Data cleaning (noise, missing values), relevance analysis (remove useless attributes), data transformation (generalisation, normalisation).

Comparing methods

Accuracy, speed, robustness (noisy/missing data), scalability, interpretability (how easy to understand).

5.2 Classification by Decision Tree Induction

A decision tree is a flowchart-like tree: internal node = test on an attribute, branch = outcome of test, leaf = class label. Easy to read and turn into IF-THEN rules.

Basic algorithm (ID3 / C4.5 / CART)

  1. Start with all training tuples at the root.
  2. If all tuples have the same class, make a leaf.
  3. Otherwise choose the best splitting attribute using an attribute selection measure.
  4. Create a branch for each outcome and partition the tuples.
  5. Repeat recursively. Stop when all tuples are in one class, no attributes remain (use majority voting), or no tuples are left.

Attribute selection measures

  • Information gain (ID3): Info(D) = −Σ pᵢ log₂ pᵢ; Info_A(D) = Σ (|Dⱼ|/|D|) × Info(Dⱼ); Gain(A) = Info(D) − Info_A(D). Choose highest gain. Biased towards attributes with many values.
  • Gain ratio (C4.5): Gain / SplitInfo – reduces that bias.
  • Gini index (CART): Gini(D) = 1 − Σ pᵢ²; choose split with the lowest Gini.

Tree pruning

Overfitting happens when the tree fits noise. Prepruning stops building early; postpruning removes branches from a full tree (cost-complexity, pessimistic pruning). Also used: handling continuous attributes by split points, scalable methods like RainForest and BOAT.

5.3 Bayesian Classification

A statistical classifier that predicts the probability that a tuple belongs to a class, based on Bayes' theorem:

P(H | X) = P(X | H) × P(H) / P(X)

H = hypothesis (tuple X is in class C), P(H|X) = posterior, P(H) = prior, P(X|H) = likelihood.

Naïve Bayesian classifier

  1. Compute P(Cᵢ) for each class = (tuples in Cᵢ)/(total).
  2. Since P(X) is the same for all classes, maximise P(X|Cᵢ)P(Cᵢ).
  3. Assume class conditional independence (attributes do not depend on each other): P(X|Cᵢ) = Π P(xₖ|Cᵢ).
  4. Predict class with the highest value.

If some probability is 0, use the Laplacian correction (add 1 to each count). Advantages: simple, fast, good accuracy. Weakness: independence assumption is often untrue. For dependencies we use Bayesian belief networks (a directed acyclic graph with conditional probability tables).

5.4 Classification by Backpropagation

Backpropagation is a neural-network learning algorithm. A multilayer feed-forward network has an input layer, one or more hidden layers and an output layer. Each connection has a weight; each unit has a bias.

Steps

  1. Initialise weights and biases with small random values.
  2. Forward pass: input is propagated; each unit computes I = Σ wᵢⱼOᵢ + θⱼ and output O = 1/(1 + e−I) (sigmoid).
  3. Backward pass: compute error. Output unit: Err = O(1−O)(T−O). Hidden unit: Err = O(1−O) Σ Errₖwⱼₖ.
  4. Update weights: w = w + (l)·Err·O and biases (l = learning rate).
  5. Repeat for all tuples (epochs) until error is small or weights converge.

Pros: high tolerance to noisy data, works with continuous inputs. Cons: long training time, poor interpretability, needs parameters like network topology. Rule extraction and network pruning help make networks readable.

5.5 Classification Based on Concepts from Association Rule Mining

Uses association rules for classification, with the class label on the right side (class association rules).

  • CBA (Classification Based on Associations): mines class association rules, sorts them by confidence/support and builds a classifier.
  • CMAR: uses FP-tree and multiple rules with weighted χ² for prediction.
  • CPAR: based on FOIL, generates rules directly, faster.

These often give better accuracy than decision trees as they search globally for combinations of attributes.

5.6 Other Classification Methods

  • k-Nearest Neighbour (lazy learner): store all training tuples; for a new tuple find the k closest (Euclidean distance) and assign majority class. No model-building, but slow when classifying.
  • Case-based reasoning: stores past cases as complex descriptions and finds similar cases to solve new problems.
  • Genetic algorithms: rules are encoded as bit strings; survival of the fittest through crossover and mutation produces better rules.
  • Rough set approach: approximates classes using lower and upper approximations; good for discarding redundant attributes.
  • Fuzzy set approach: gives degrees of membership (0 to 1), e.g. income 48,000 is "0.6 medium and 0.4 high".

5.7 Prediction

Prediction of numeric values is done by regression.

  • Linear regression: y = w₀ + w₁x. Weights by least squares: w₁ = Σ(xᵢ−x̄)(yᵢ−ȳ) / Σ(xᵢ−x̄)², w₀ = ȳ − w₁x̄.
  • Multiple regression: y = w₀ + w₁x₁ + w₂x₂ + …
  • Nonlinear / polynomial regression: transform to a linear form (e.g. y = w₀ + w₁x + w₂x²).
  • Generalised linear models: logistic regression (predicts probability of a class), Poisson regression.
  • Other predictors: regression trees, model trees, neural networks.

5.8 Classifier Accuracy

Confusion matrix (for class "positive"): TP, TN, FP, FN.

  • Accuracy = (TP + TN)/(P + N); Error rate = 1 − accuracy.
  • Sensitivity (recall) = TP/P; Specificity = TN/N; Precision = TP/(TP+FP).

Estimating accuracy

  • Holdout: e.g. 2/3 for training, 1/3 for testing. Random subsampling: repeat holdout k times.
  • k-fold cross-validation: split into k parts; train on k−1, test on 1; repeat k times; average. Leave-one-out for small data; stratified keeps class proportions.
  • Bootstrap: sample with replacement; about 63.2% tuples chosen for training, rest for testing.

Improving accuracy: ensemble methods – bagging (vote of classifiers on bootstrap samples) and boosting (AdaBoost: misclassified tuples get higher weight in the next round). Use ROC curves and compare models with significance tests.

5.9 Cluster Analysis – Introduction

Clustering groups data objects into clusters so that objects within a cluster are highly similar and different from objects in other clusters. It is unsupervised (no predefined classes). Applications: customer segmentation, image recognition, document grouping, biology, fraud detection.

Requirements of good clustering

Scalability, ability to handle different attribute types, discovering arbitrary-shaped clusters, minimal input parameters, handling noise and outliers, insensitivity to input order, high dimensionality, interpretability.

5.10 Types of Data in Cluster Analysis

  • Data matrix: n objects × p variables (object-by-variable).
  • Dissimilarity matrix: n × n table of distances d(i, j); d(i,i) = 0 and d(i,j) = d(j,i).
  • Interval-scaled variables: continuous measurements. Standardise first (z-score using mean absolute deviation). Distances: Euclidean √Σ(xᵢₖ−xⱼₖ)², Manhattan Σ|xᵢₖ−xⱼₖ|, Minkowski (generalisation with power q).
  • Binary variables: symmetric (both values equal importance) or asymmetric. Dissimilarity: (r+s)/(q+r+s+t) symmetric; Jaccard (r+s)/(q+r+s) asymmetric.
  • Nominal (categorical): d = (p − m)/p, where m = matches.
  • Ordinal: replace rank by zᵢ = (rank−1)/(M−1), then treat as interval-scaled.
  • Ratio-scaled: apply logarithm or treat as continuous.
  • Mixed types: combine all with a weighted formula.

5.12 Partitioning Methods

Given n objects, construct k partitions (k ≤ n); each cluster has at least one object, each object in one cluster.

k-Means (centroid-based)

  1. Choose k objects as initial cluster centres.
  2. Assign each object to the nearest centre (mean).
  3. Recompute the mean of each cluster.
  4. Repeat 2–3 until no change.

Objective: minimise E = Σ Σ |p − mᵢ|². Example: points 2, 4, 10, 12, 3, 20, 30, 11, 25 with k=2 and initial centres 2 and 4 converge to clusters {2,3,4,10,11,12} and {20,25,30}.
Pros: simple, fast O(nkt). Cons: need k in advance; sensitive to outliers; only spherical clusters; local optimum.

k-Medoids (PAM)

Uses an actual object (medoid, most central) as the cluster representative instead of a mean, so it is less affected by outliers. PAM swaps a medoid with a non-medoid if cost reduces. Costly for large data; CLARA (uses samples) and CLARANS (randomised search) scale better.

5.13 Density-Based Methods

Clusters are dense regions separated by low-density regions; can find arbitrary shapes and handle noise.

DBSCAN

  • ε (eps): radius of neighbourhood. MinPts: minimum points in ε-neighbourhood.
  • Core object: has ≥ MinPts points within ε. Border point: within ε of a core object but not core itself. Noise: neither.
  • Directly density-reachable, density-reachable (chain of core objects), density-connected (both reachable from a common object).

Algorithm: pick an unvisited point; if it is a core object, form a cluster and keep adding all density-reachable points; else mark as noise. Complexity O(n log n) with spatial index. OPTICS gives a cluster ordering for many ε values; DENCLUE uses density functions (influence of each point) and hill-climbing.

5.14 Grid-Based Methods

Divide space into a finite number of cells forming a grid; clustering is done on cells, so time depends on the number of cells, not data objects – very fast.

  • STING: hierarchical rectangular cells at different resolutions, with statistics (count, mean, std, min, max, distribution) stored; queries answered top-down.
  • WaveCluster: applies wavelet transform to the grid to find dense regions; handles noise well.
  • CLIQUE: grid- and density-based; finds clusters in subspaces of high-dimensional data using the Apriori-like principle.

5.15 Model-Based Clustering Methods

Assume a mathematical model for each cluster and find the best fit.

  • EM (Expectation-Maximization): each object belongs to clusters with probabilities (mixture of Gaussians). E-step: compute membership probabilities; M-step: re-estimate parameters; repeat until convergence. An extension of k-means.
  • COBWEB: conceptual clustering that builds a classification tree incrementally using category utility.
  • SOM (Self-Organising Maps): neural network that maps high-dimensional data onto a 2-D grid of neurons, keeping similar objects near each other.

5.16 Outlier Analysis

An outlier is a data object that is inconsistent with the rest of the data. One person's noise is another's signal: used in fraud detection, intrusion detection, medical analysis.

Methods

  • Statistical (distribution-based): assume a distribution (e.g. normal) and flag objects with very low probability; uses discordancy tests. Drawback: distribution is often unknown.
  • Distance-based: an object O is a DB(p, D)-outlier if at least fraction p of objects are farther than D from it. Algorithms: index-based, nested-loop, cell-based.
  • Density-based local outliers: uses the Local Outlier Factor (LOF); compares local density with neighbours' density – finds outliers in regions of varying density.
  • Deviation-based: identifies objects that deviate from the main characteristics of a group (sequential exception technique, OLAP data-cube approach).
